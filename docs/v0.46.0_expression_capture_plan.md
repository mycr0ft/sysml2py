# v0.46.0 — Structured Expression Capture (Capture-Don't-Evaluate)

> **Status:**
> - **Phase 0 (prerequisite) — DONE in v0.48.0**: assert constraint /
>   constraint / calc / state / action / requirement / satisfy /
>   allocation usages inside `part def`, `item def`, etc. bodies
>   now survive `Part.load_from_grammar` into the public-API tree.
>   10 regression tests in `tests/grammar_test.py::*v046_phase0*`.
> - **Phase 1 (expression refactor) — DONE in v0.52.0**: visitor
>   now emits a structured expression dict with operators
>   captured at the correct layer, using a precedence-climbing
>   pass to recover the correct operator order from the
>   left-associative ANTLR parse. 10 regression tests in
>   `tests/grammar_test.py::*v046_phase1` (binary equality,
>   invocation, feature chain, arithmetic precedence, unary minus,
>   `not` operator, logical `and`/`or` (text-preservation fallback),
>   conditional ternary (layer-presence), range, structural
>   non-collapse). Known limitations:
>   - `and`/`or`/`xor`/`implies` fall back to text preservation
>     (the grammar classes use list-based operand/operator fields
>     that don't fit the chain layout).
>   - `a.b` field access falls back to text preservation
>     (the grammar class lacks a `FeatureChainExpression` that
>     `BaseExpression` can read).
>   - The grammar's `IF ? :` ternary form is not currently
>     parseable inside `calc` bodies (known grammar limitation).
> **Author:** Context from issue #3 triage + codebase investigation.
> **Target release:** v0.48.0 (Phase 0), v0.52.0 (Phase 1)
> **Estimated effort:** ~1 week (see §8).

## 1. Problem

Today, `_visit_owned_expression` (`src/sysmlpy/antlr_visitor.py:10557`) collapses
**every** non-literal expression into a single `FeatureReferenceMember` whose
`memberElement` is a `QualifiedName` with the **whole expression text** as a
single name part. Example:

```python
assert constraint { radius == zero }
# visitor emits:
#   FeatureReferenceExpression
#     FeatureReferenceMember
#       QualifiedName { names: ["radius==zero"] }   # ← entire text, structure lost
```

The wrapping `EqualityExpression` / `AdditiveExpression` / … chain in
`_wrap_expression_layers` is emitted with **empty operator/operand arrays** for
every binary layer, so the operator is never captured. Round-trip works only
because `QualifiedName.dump()` returns the raw text verbatim.

This makes a future name resolver infeasible: a resolver needs individually
addressable `FeatureReferenceExpression` nodes (one per identifier) so it can
look each up in the symbol table. With the current lossy collapse, the resolver
would have to re-parse raw text — duplicating grammar work and drifting from
the ANTLR grammar.

A second, related bug blocks testing: `assert constraint` inside a `part def`
body is **dropped** by `Part.load_from_grammar` in `src/sysmlpy/usage.py:782`.
That dispatch handles `PartDefinition` / `ItemUsage` / `AttributeUsage` / etc.
but has no branch for `AssertConstraintUsage` / `ConstraintUsage` /
`CalculationUsage`. The visitor emits the assert constraint correctly; the
grammar classes construct it correctly; `usage.py` discards it when building
the public-API `Part` tree. So `model.dump()` silently omits every assert
constraint inside a part. This must be fixed first so expression-capture tests
can even observe the round-trip.

## 2. Goal

Replace the lossy single-`FeatureReferenceMember` collapse with a **structured
expression dict** that preserves operator structure, so a future v0.47+ name
resolver can walk identifiers individually.

**In scope:**
- Prerequisite: plumb `AssertConstraintUsage` / `ConstraintUsage` /
  `CalculationUsage` / `StateUsage` / `ActionUsage` through
  `Part.load_from_grammar` so they survive into the public-API `Part.children`.
- Refactor `_visit_owned_expression` to walk the ANTLR `ownedExpression`
  subtree and emit per-rule dicts keyed on the expression kind
  (`BinaryExpression`, `InvocationExpression`, `FeatureChainExpression`,
  `LiteralInteger`, `LiteralReal`, `LiteralString`, `LiteralBoolean`,
  `FeatureReferenceExpression`, `MetadataAccessExpression`,
  `ConstructorExpression`, `CastExpression`, `ConditionalExpression`,
  `UnaryExpression`, `ParenthesizedExpression`, `IfExpression`).
- Add matching grammar classes in `grammar/classes.py` for any new dict shapes
  that don't already have a class (most already exist — see §4).
- Public API: `Model.find_expressions()` helper that walks
  `assertConstraintUsage` / `calculationUsage` / `requirementUsage` and yields
  `(constraint, expression)` pairs.
- Documentation: README + STATUS + CHANGELOG.

**Out of scope (deferred to v0.47+):**
- Name resolution (looking up identifiers in the symbol table).
- Type checking (verifying operand types are compatible).
- OCL evaluation (evaluating the expression to a value).
- Constraint-body semantic checks (the "check" half of "parse + check").

## 3. Architecture: the capture layer

```
SysML text
  → ANTLR4 parse tree (ownedExpression context tree)
  → _visit_owned_expression (REFACTORED)
  → structured OwnedExpression dict
  → grammar/classes.py (OwnedExpression / ConditionalExpression / …)
  → dump() / get_definition() round-trip
  → (future v0.47+) semantic.py walks the structured dict, resolves names
```

The refactor touches only the visitor emission and the grammar-class
construction. Everything downstream (the `OwnedExpression` /
`ConditionalExpression` / `EqualityExpression` / … class hierarchy in
`grammar/classes.py:5539-6350`) already exists and already round-trips — the
problem is that the visitor never **fills** the operator/operand arrays, so
the classes get empty data.

### Phase 1 — Visitor refactor: structured expression emission

**File:** `src/sysmlpy/antlr_visitor.py`.

Replace `_visit_owned_expression` (line 10557) with a dispatcher that walks
the ANTLR `ownedExpression` context tree and fills the existing expression
chain with real operator/operand data instead of empty arrays.

**Key insight:** the ANTLR `ownedExpression` rule is left-recursive with
operator precedence (see `SysMLv2Parser.g4:22-62`). ANTLR parses
`radius == zero` as:

```
ownedExpression
  : ownedExpression EQ_EQ ownedExpression    # the == alternative
      ↳ lhs: ownedExpression (baseExpression)
      ↳ rhs: ownedExpression (baseExpression)
```

ANTLR's Python runtime exposes this as: `oe_ctx.getChildCount() == 3`,
`oe_ctx.getChild(0)` is the lhs `ownedExpression`, `oe_ctx.getChild(1)` is
the `EQ_EQ` terminal, `oe_ctx.getChild(2)` is the rhs `ownedExpression`.
For unary prefix (`-x`, `not x`): `getChildCount() == 2`,
`getChild(0)` is the operator terminal, `getChild(1)` is the operand.
For the base case (`baseExpression`): `oe_ctx.baseExpression()` is non-null.

**New helper functions** (add near `_visit_owned_expression`):

```python
def _emit_expression(oe_ctx):
    """Walk an ownedExpression context and return a structured OwnedExpression
    dict. Dispatches on ANTLR child shape: binary operator, unary operator,
    conditional (if/then/else), or base expression."""
    ...

def _emit_binary_expression(lhs_ctx, op_terminal, rhs_ctx):
    """Fill the EqualityExpression / RelationalExpression / AdditiveExpression /
    MultiplicativeExpression / ExponentiationExpression / RangeExpression /
    AndExpression / OrExpression / XorExpression / ImpliesExpression /
    NullCoalescingExpression / ConditionalExpression layers with real operator
    and operand data."""
    ...

def _emit_unary_expression(op_terminal, operand_ctx):
    """Fill the UnaryExpression layer with the operator and operand."""
    ...

def _emit_conditional_expression(if_ctx, then_ctx, else_ctx):
    """Fill the ConditionalExpression layer with condition/then/else."""
    ...

def _emit_base_expression(base_ctx):
    """Dispatch a baseExpression to the right primary: literal, feature
    reference, invocation, constructor, body expression, cast, or
    parenthesized expression."""
    ...
```

**Strategy for `_emit_binary_expression`:** the existing
`_wrap_expression_layers` builds the empty chain. Reuse it as a skeleton, but
instead of passing a single `primary_expression` at the bottom, walk the lhs
and rhs recursively and splice them into the right operator layer. Map the
operator terminal to the layer:

| Operator terminal(s) | Expression layer (existing class) |
|---|---|
| `EQ_EQ`, `BANG_EQ`, `EQ_EQ_EQ`, `BANG_EQ_EQ` | `EqualityExpression` |
| `LT`, `GT`, `LE`, `GE` | `RelationalExpression` |
| `PLUS`, `MINUS` | `AdditiveExpression` |
| `STAR`, `SLASH`, `PERCENT` | `MultiplicativeExpression` |
| `STAR_STAR`, `CARET` | `ExponentiationExpression` |
| `DOT_DOT` | `RangeExpression` |
| `AMP` | `AndExpression` |
| `PIPE` | `OrExpression` |
| `XOR` | `XorExpression` |
| `IMPLIES` | `ImpliesExpression` |
| `QUESTION_QUESTION` | `NullCoalescingExpression` |
| `IF` / `QUESTION` / `ELSE` (ternary) | `ConditionalExpression` |

For each binary node, emit:
```python
{
  "name": "<LayerName>Expression",       # e.g. "EqualityExpression"
  "operator": [op_text],                 # e.g. ["=="]
  "operand": [lhs_dict, rhs_dict],        # two operands, recursively structured
  # ...nested layers below this one, filled by recursing into lhs/rhs...
}
```

**Critical:** keep the existing nested-layer structure (the
`ConditionalExpression → NullCoalescingExpression → ImpliesExpression → … →
PrimaryExpression` chain) so existing grammar classes still work. The change
is that the operator/operand arrays are now **populated** with real data
instead of empty.

**Backstop:** if `_emit_expression` can't recognize a shape (defensive — should
not happen for valid SysML), fall back to the existing
`_make_feature_reference_primary(text)` path. Print a `[expression] unhandled
X` warning (mirrors the AGENTS.md catch-all pattern). This preserves the
graceful-fallback contract.

### Phase 2 — Grammar class `dump()` fixes

**File:** `src/sysmlpy/grammar/classes.py`.

The existing `dump()` methods on `EqualityExpression`, `RelationalExpression`,
`AdditiveExpression`, `MultiplicativeExpression`, `ExponentiationExpression`,
`UnaryExpression`, `ConditionalExpression` currently join operands with no
operator text (because the visitor never filled operators). After Phase 1,
the visitor fills operators, so `dump()` must emit `lhs OP rhs`.

**Pattern** (apply to each binary-expression class):
```python
def dump(self):
    parts = []
    for i, operand in enumerate(self.operands):
        parts.append(operand.dump())
        if i < len(self.operator):
            parts.append(self.operator[i])   # the operator string
    return " ".join(parts)   # or "" .join, matching existing whitespace
```

Audit each class's existing `dump()` and adjust. Verify against the
failing-first tests from Phase 0 + new expression regression tests.

**For `UnaryExpression`:**
```python
def dump(self):
    if self.operator:
        return f"{self.operator} {self.operand.dump()}"   # or no space, per grammar
    return self.operand.dump()
```

**For `ConditionalExpression` (if/then/else):**
```python
def dump(self):
    # if cond ? then : else  →  SysML syntax is "if cond then x else y"
    # Verify the exact SysML v2 syntax for conditional expressions.
```

**Risk:** whitespace. Existing tests use `strip_ws(text) == strip_ws(dump())`,
so whitespace differences are tolerated. But new tests should use exact
whitespace where it matters for readability.

Also add a **structural** test (not just text round-trip) to lock in the dict
shape so a future resolver has something to walk:

```python
def test_expression_dict_has_equality_layer_gh3_capture():
    """The visitor must emit a populated EqualityExpression, not an empty one
    with the whole text collapsed into a FeatureReferenceMember."""
    from sysmlpy.antlr_parser import parse
    from sysmlpy.antlr_visitor import _visit_root_namespace_dict
    text = """package P {
        part def W {
            attribute r;
            assert constraint { r == zero }
        }
    }"""
    d = _visit_root_namespace_dict(parse(text))

    def find_first(node, target):
        if isinstance(node, dict):
            if node.get("name") == target:
                return node
            for v in node.values():
                r = find_first(v, target) if isinstance(v, (dict, list)) else None
                if r: return r
        elif isinstance(node, list):
            for it in node:
                r = find_first(it, target) if isinstance(it, (dict, list)) else None
                if r: return r
        return None

    eq = find_first(d, "EqualityExpression")
    assert eq is not None, "EqualityExpression layer missing entirely"
    assert len(eq.get("operator", [])) >= 1, \
        f"EqualityExpression has no operator; got: {eq!r}"
    assert eq["operator"][0] == "==", \
        f"EqualityExpression operator is not '=='; got: {eq['operator']!r}"
```

## 6. Risk mitigations

| Risk | Mitigation |
|---|---|
| Existing `strip_ws(text) == strip_ws(dump())` tests break | Each emitter preserves child text via `getText()` or by recursing into structured children. Whitespace behavior shouldn't change. If a test breaks, STOP. |
| Deep operator precedence double-emits | Write the deeply-nested test (`a + b * c == 0`) FIRST, before refactoring. Commit it as the regression bar. |
| 354 grammar classes — adding new ones is small | Audit first; most classes already exist. Only add what's missing. |
| `Part.load_from_grammar` prerequisite fix breaks other tests | The fix only ADDS branches for previously-dropped usage kinds; it doesn't change existing branches. Existing tests for parts/items/attributes are unaffected. |

| Conformance baseline shifts | Must stay at 118/123 with byte-identical failures. If it shifts, STOP. |

## 7. What this enables (v0.47+)

A name resolver becomes feasible because every name reference inside an
expression is now an individually-addressable `FeatureReferenceExpression`
(with its `FeatureChainExpression` chain) rather than buried inside raw text.

**v0.47+ name resolver sketch:**
1. Walk `assertConstraintUsage` → `calculationBody` → `resultExpressionMember`
   → `ownedExpression` (recursive).
2. At each `FeatureReferenceExpression`, resolve the `qualifiedName` against
   the `SymbolTable` (already built by `semantic.py`).
3. At each `FeatureChainExpression`, resolve the source's type, then resolve
   each chain step on that type (extending `_check_feature_chaining_compatible`
   in `semantic.py:1800`).
4. Emit `SemanticIssue`s for unresolved names.

**v0.48+ type checker:** verify operand types are compatible for each binary
operator (e.g. `==` requires matching types, `+` requires numeric types).

**v0.49+ OCL evaluation:** evaluate the expression to a value (for `assert
constraint` verification).

This is what gets you from "parse-clean but not checked" to "parse-clean AND
names checked". Type-checking / OCL evaluation remain out of scope for v0.47.
